# Steam 游戏陈列库

一个本地优先的个人 Steam 游戏目录。管理模式的数据保存在浏览器 `localStorage` 并自动备份到项目磁盘，封面也会下载到本地；公开模式固定读取仓库中发布的数据，不受访客浏览器旧缓存影响。不需要数据库或第三方运行时依赖。

公开访问默认只显示陈列内容，不显示管理工具栏，也不会向本地备份接口写入。仅在运行项目的本机访问 `http://127.0.0.1:4173/?admin=1` 才会进入管理模式；公网域名即使附带该参数也不会启用管理功能。

## 启动

需要 Node.js 20 或更高版本：

```powershell
npm.cmd start
```

然后访问 <http://127.0.0.1:4173>。项目使用 ES Modules 和本机 Steam API 转发，因此不再支持直接双击 `index.html` 运行。

## 常用命令

```powershell
npm.cmd start       # 启动本地应用
npm.cmd test        # 运行单元测试和本地服务测试
npm.cmd run check   # 语法检查 + 全部测试
npm.cmd run publish:prepare # 将最新本机备份与封面同步到公开版本
```

这里显式使用 `npm.cmd`，可避开部分 Windows PowerShell 环境对 `npm.ps1` 的执行策略限制。

## 项目结构

```text

data/
  default-library.json     首次访问时使用的默认陈列库
  archive/                 原始导出快照，仅作留档，不会由服务公开
  backups/                 按浏览器分别保存的自动备份与历史版本（不入 Git）
  covers/                  下载成功的封面图片，重启后仍可用（不入 Git）
src/
  app.js                   页面状态与交互编排
  card-effects.js           卡牌鼠标倾斜与闪卡反光（事件委托、按帧更新）
  cover-palette.js          封面主色提取、配色缓存与镀层颜色应用
  cover-assets.js           公开封面尺寸与预计算配色清单
  rarity.js                 七档珍藏定义、旧分数换算与档次排序
  domain.js                游戏模型、筛选、合并、VDF 解析等纯逻辑
  storage.js               localStorage 版本迁移与备份格式
  local-backup.js           自动备份队列、保存状态与失败重试
  steam.js                 浏览器端 Steam 服务调用
tests/                     Node 内置测试
services/cover-proxy.mjs    限定 Steam CDN 的封面读取与有界缓存
services/library-backup.mjs 本机游戏库备份，保留历史版本并隔离浏览器
services/local-files.mjs    临时文件写入后原子替换
tools/legacy/              旧版一次性数据脚本，仅作历史参考
tools/prepare-public.mjs   发布前同步最新备份、压缩封面并自动计算闪卡配色
tools/image-runtime.mjs    复用项目或 Codex 已安装的 sharp 图像处理环境
server.mjs                 静态文件服务和本机 Steam API 转发
```

## GitHub Pages 发布

GitHub Pages 使用仓库根目录的静态文件。发布前先在本机管理员模式确认数据已自动备份，然后运行 `npm.cmd run publish:prepare`。该命令会把最新的 `data/backups/*/latest.json` 同步为 `data/default-library.json`，自动生成 320px / 460px WebP 封面和 `assets/covers/manifest.json` 配色清单。每次新增游戏都会自动参与处理，无需手动提色。压缩图使用内容指纹命名，更新封面后浏览器会下载新版本。图像处理复用项目或 Codex 中已有的 sharp；其他电脑可先在项目中安装 sharp。

随后运行 `git add -A`、`git commit -m "更新陈列库"` 和 `git push origin HEAD:main`，Pages 会自动重新部署。

公开页面使用相对资源路径，因此支持 `https://fried-piggy.github.io/Steam-/` 这样的项目子路径。公开模式只读取提交后的默认数据和静态封面，不启用本机管理功能。

## 陈列室与集卡册

- **殿堂珍藏**：保存「管理排序」后，按个人顺序展示前三款游戏，第一名居中，第二、三名分列两侧，使用金 / 银 / 铜卡框与展台。没有设置个人顺序时，仍从已定级游戏中按档次、名称和 ID 取前三名。筛选、翻页及临时切换排序不会改变殿堂排名；隐藏的旧分数不参与排名。
- **收藏卡册**：其余游戏每页十二张，桌面端每行三张、共四行，卡牌尺寸和间距保持不变，带装订环、透明卡套和翻页按钮。搜索、类型筛选和排序会回到第一页；前三名不会重复出现在卡册中，匹配到它们时会有文字提示。
- **3D 闪卡**：鼠标在卡套内移动时，卡牌以中心沿 X/Y 轴倾斜，镀层与高光跟随鼠标反射，移出后回正。普通卡从实际加载成功的封面提取两个代表色，并生成同色系浅色高光；黑白封面与提色失败使用银色镀层。前三名使用完整彩虹镀层与抛光金银铜卡面。动效只更新当前卡牌，使用 `requestAnimationFrame` 合并事件，静止时无持续动画循环。
- **弹性拖拽**：桌面端可按住卡牌的非按钮区域拖动，卡套位置保持固定；卡牌会根据拖动方向倾斜，松手后按照释放速度弹性归位，回弹途中也能再次抓取。发生拖动后会吞掉随后的点击，避免误触编辑或删除。
- **封面加载与提色**：公开页面自动选择 320px / 460px WebP，前三名立即加载、第一名优先，其余按浏览器懒加载；不再加载重复的模糊背景图。公开页面直接读取发布清单中的配色，无需 Canvas 采样或额外请求。管理员新增游戏后，封面加载成功即从同一张图片自动提色，结果缓存在内存与 `steam_cover_palettes_v1`，七天内复用。发布时所有游戏的配色会自动重新生成。
- **触屏与减少动态效果**：手指直接滑动卡牌时正常滚页；在卡牌非按钮区域保持约 160ms 后进入拖动，松手使用弹簧回弹。长按前移动超过 8px、滚动已开始、多指操作及系统取消都会让出手势。系统开启「减少动态效果」时禁用拖动动画。

公开卡牌将编辑按钮腾出的空间分配给评论，按卡面剩余高度显示，手机端也不再固定截断为两行。卡牌高度保持原样，特别长的评论仍会在卡面底部裁切。

手机拖动每帧只提交一次 `transform`，沿用已绘制的静态闪卡纹理，不逐帧重算布局、渐变或光斑；拖动与回弹期间暂停整页徽章动画。回弹按实际经过时间计算，掉帧不会拖慢弹簧进度。电脑鼠标悬停仍会改变闪卡反光。

视觉样式位于 `assets/exhibition.css`；表单与弹窗的基础样式仍位于 `assets/styles.css`。

## 类别与卡面主题

- 编辑游戏时可勾选多个类别，卡牌完整显示全部标签，筛选和类型统计包含每个标签。
- 七种卡面底色：解谜 / 琥珀黄、节奏 / 玫瑰粉、多人合作 / 天蓝、探索向 / 翡翠绿、肉鸽 / 暗红、2D类银河恶魔城 / 紫罗兰、视觉小说 / 薰衣草灰蓝。可从已选类型中指定卡面主题；没有匹配类型时沿用默认透明卡面。
- 普通卡仍使用封面提取的闪卡反光；只有前三名使用更鲜明的抛光金银铜卡框和完整彩虹色谱反光，类别底色不覆盖荣誉卡面。
- 备份格式版本为 3，使用 `genres` 数组、`cardTheme` 和 `tier` 保存设置。旧单类别 `genre` 自动兼容，Roguelike / 音乐节奏旧标签会转换为肉鸽 / 节奏；历史归档文件保留原样。

## 七档珍藏与稀有度徽标

顶部「管理排序」包含全部游戏，可上下移动，或输入目标名次后点击「移动」；搜索只缩小显示范围，名次始终是全库名次。点击「保存排序」后生效，取消不会改动游戏库。个人顺序保存在每款游戏的 `manualOrder` 字段中，随浏览器数据、磁盘备份及导出一起保存。修改游戏档次或手动添加游戏后，会将该游戏插入新档次的末尾；没有同档游戏时放在首个较低档次之前，暂不定级排在末尾。仅移动这一款，其余游戏的手动相对顺序不变；只改名称、短评等不会触发移动。批量导入的新游戏仍追加到末尾。页面默认选中「我的排序」，也可以临时切换到档次、名称或最近添加。个人顺序不改变游戏档次与历史分数。

页面不再使用数字分数。添加/编辑游戏时选择 UR（人生级作品）、SSR（挚爱神作）、SR（非常优秀）、R（优秀）、N（不错）、C（一般）、F（不喜欢），或暂不定级。每档的完整定义与判断标准统一维护在 `src/rarity.js`，也显示在表单内。搜索框支持输入准确档次（如 SSR）筛选。

卡牌右上角叠贴立体金属字徽章，只显示档次字母与星芒，不显示下方定义文字，不占用布局空间；卡面沿用原来的各部分比例，封面铺满图片区域、允许裁切。高档增加流动反光与光晕：SR 紫晶、SSR 金光、UR 幻彩。普通卡原来的卡面主题与封面提色保持独立。徽章动画在拖动/回弹时暂停，并尊重系统「减少动态效果」。视觉样式位于 `assets/rarity.css`。

现存 `rating` 字段仅作历史存档，保留原值，不显示、不可编辑、不用于排序；新游戏只保存 `tier`，不生成数字分数。无 `tier` 的旧记录首次读取时按 ≥9.5 → UR、≥9 → SSR、≥8 → SR、≥7 → R、≥6 → N、≥4 → C、其余正分 → F 换算，零分仍未定级。旧 v2 五分制只在推导档次时换算，原始分数不变。显式选择「暂不定级」不会被旧分数再次填回。浏览器存储键保持不变，自动备份与导出继续保留历史分数。

## 封面加载与旧数据兼容

封面通过 `/api/steam/covers/<App ID>?variant=auto` 优先读取 `data/covers/` 的本地图片。没有缓存时，同时尝试 Steam 商店接口返回的真实 `header_image` 和原来的四个 CDN 地址，支持 MOLE 等使用哈希子目录的游戏，也不会让旧游戏等待商店接口超时。成功图片自动下载为 JPG/PNG/WebP，重启后直接读取磁盘。卡牌、编辑预览、搜索缩略图与闪卡提色使用同一套封面来源。无需 Steam API Key。

真实图片仅允许来自指定 Steam CDN、属于该 App ID 的 JPEG/PNG/WebP，且不跟随重定向。成功封面继续使用有界缓存。旧的 `variant=0..3` 提色接口保持兼容。

这项变更不改变游戏数据结构、存储键或备份格式，不需要重新导入。请继续使用原来的浏览器及 `http://127.0.0.1:4173`，因为浏览器本地数据按访问地址隔离。

## 自动保存到本机

打开页面以及新增、编辑、导入、删除游戏后，会自动将当前游戏库备份到 `data/backups/<浏览器标识>/latest.json`。每个变化的版本另存一份带时间的 JSON，历史版本不会自动删除，相同内容不重复生成。页面统计下方显示保存成功的游戏数和时间；失败时保留浏览器数据，每 30 秒重试。

Edge、VS Code 内置浏览器及不同访问地址仍有各自的浏览器存储；磁盘备份也分别留档，避免默认库覆盖 Edge 中的完整收藏。此功能是自动备份，不会自动把另一浏览器的游戏库合并到当前页面。需要恢复或迁移时，使用「导入备份」选择对应目录里的 JSON；现有导入功能保留同 App ID 的当前记录，因此恢复被改动的档次时需留意这一规则。

保存备份后，服务会在后台以两个并发任务下载库中游戏的封面，因此不必逐页打开才能缓存图片。未成功的下载会在后续备份请求时重试（失败冷却 15 分钟）；首次下载仍需联网，已有缓存不依赖 Steam。备份和图片目录不加入 Git，也不会由静态文件服务直接公开。

## 数据与安全

- 当前数据使用 `steam_game_library_v4` 保存；首次运行会自动迁移旧版 v2/v3 数据。
- 导入的 JSON 会经过字段长度、类型、珍藏档次和重复项校验，合法的历史分数字段原样留档。
- 页面不把游戏名称或短评拼接为 HTML，避免导入文件造成脚本注入。
- Steam Web API Key 不会写入 `localStorage`，也不会经过公共 CORS 代理；本机服务只在单次请求中将它发送给 Steam 官方接口。
- 本地服务只公开运行应用需要的 `index.html`、`assets/`、`src/` 和默认数据，不公开归档与工具目录。

## 导入方式

1. **VDF（推荐）**：选择 Steam 的 `userdata/<ID>/config/localconfig.vdf`。文件在浏览器内解析，游戏名称再经本机服务查询。
2. **Steam Web API**：输入 API Key 和 17 位 Steam ID，同步拥有的游戏。
3. **JSON 备份**：从页面导出或导入版本化备份；也兼容旧版数组格式。
